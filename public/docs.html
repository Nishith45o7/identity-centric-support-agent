Contextis Developer Documentation

AI support infrastructure that remembers every customer across their entire lifecycle.

Core Positioning

Contextis enables software teams to integrate an intelligent support agent into their applications using a modern REST API and an embeddable chat widget. The agent recalls customer preferences, past issues, and authorized tool results without requiring manual prompt engineering or memory management from the host application.

5-Minute Quickstart

1. Sign up for a Contextis developer account at contextis.io/signup.

2. Create your project in the Developer Console and copy your pk_live_... (widget) or sk_live_... (server) key.

3. Drop the embeddable script onto your website, or call the REST chat endpoint from your backend.

API Keys & Environments

Contextis separates client-side identifiers from server-side secrets with distinct key prefixes and environments:

Public Keys pk_live_... or pk_test_...: Safe for public browsers and mobile apps. Restricted to chat widget initialization and public customer endpoints.

Secret Keys sk_live_... or sk_test_...: For server-to-server operations. Hashes are securely stored. Secret keys are never exposed in browser code.

Passing API Keys

Pass your secret key in the standard Authorization header:

Authorization: Bearer sk_live_your_secret_key_here

REST Chat API

POST /v1/support/chat

Sends a customer message to the Contextis agent orchestrator, retrieves historical memory, executes authorized tools if needed, and returns the contextual response.

Request Snippet (Multi-Language)

curl -X POST https://api.contextis.io/v1/support/chat \
  -H "Authorization: Bearer sk_live_your_secret_key" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "cust_alex_99",
    "message": "Is my package still delayed?",
    "conversation_id": "conv_849201"
  }'
// Browser or Client-side (using Public Key pk_*)
const response = await fetch('https://api.contextis.io/v1/support/chat', {
  method: 'POST',
  headers: {
    'x-api-key': 'pk_live_your_public_key',
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    user_id: 'cust_alex_99',
    message: 'Is my package still delayed?',
    conversation_id: 'conv_849201'
  })
});
const data = await response.json();
console.log(data.reply);
// Node.js Backend (Server-to-Server)
import axios from 'axios';

const { data } = await axios.post(
  'https://api.contextis.io/v1/support/chat',
  {
    user_id: 'cust_alex_99',
    message: 'Is my package still delayed?',
    conversation_id: 'conv_849201'
  },
  {
    headers: {
      Authorization: `Bearer ${process.env.CONTEXTIS_SECRET_KEY}`,
      'Content-Type': 'application/json'
    }
  }
);

console.log('AI Response:', data.reply);
console.log('Memory Recalled:', data.memory_used);
# Python 3
import requests
import os

response = requests.post(

    headers={
        "Authorization": f"Bearer {os.getenv('CONTEXTIS_SECRET_KEY')}",

    },

payload = response.json()

Customer Identity & Memory Architecture

Every customer is identified uniquely by the compound key: (organization_id, project_id, external_user_id).

Key Rule: Memory is Context, NOT Authentication

Contextis automatically extracts useful preferences, past friction points, and unresolved tickets. However, remembered data is purely conversational context—it never replaces cryptographic authorization or account passwords.

Tools & Business Action Router

Configure business APIs (e.g. order tracking, invoice search, ticket submission) that the agent can call dynamically. Tools execute within a strict permission matrix:

  • READ: Fetch orders, tracking status, shipping updates
  • WRITE: Create ticket, add order note, update notification preference
  • SENSITIVE: Trigger verified password reset, send confirmation code
  • ADMIN: Account changes requiring explicit human confirmation

Secure Password Reset Workflow

Crucial Rule: The Contextis agent NEVER asks for, records, or accepts raw user passwords.

Customer: "I forgot my password."
Agent:    "I can help send a secure reset link. What email is on your account?"
Customer: "alice@example.com"
Agent:    [Calls send_password_reset tool via business authentication provider]
Response: "A verified reset email has been dispatched to alice@example.com."

Security & Multi-Tenancy

Strict multi-tenant isolation is enforced server-side on every request. Client-supplied tenant IDs are never trusted. All database queries, memory lookups, and audit trails scope to the authenticated organization.

Outbound Webhooks

Contextis dispatches real-time HTTPS webhooks for critical lifecycle events. Deliveries are cryptographically signed using your webhook secret via HMAC-SHA256.

Signature Verification

Every delivery includes the signature header:

X-Contextis-Signature: sha256=d5b3f2...hash

Verify the payload in Node.js:

const crypto = require('crypto');
const expected = 'sha256=' + crypto.createHmac('sha256', secret).update(rawBody).digest('hex');
const isValid = crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(expected));

Supported Events

  • conversation.created: New customer session opened
  • conversation.resolved: Issue resolved by AI or agent
  • conversation.escalated: Human agent handoff requested with complete context dossier
  • feedback.created: Customer submitted helpful/unhelpful rating

Standard Error Codes

All API errors return consistent JSON payloads with an unambiguous requestId:

  "error": {
    "code": "ORGANIZATION_SUSPENDED",
    "message": "This organization has been suspended. Please contact platform support.",
    "requestId": "req_839023471"
  }
